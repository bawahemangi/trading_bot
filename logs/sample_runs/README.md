# Sample log run

`demo_market_limit_stoplimit.log` was generated by running the real CLI
(`cli.py`) end-to-end — real HTTP requests, real HMAC-SHA256 signing, real
logging pipeline — against a **local mock Binance server**
(`scripts/mock_binance_server.py`), not against the live testnet.

This is because the sandboxed environment this bot was developed in has
no outbound network route to `testnet.binancefuture.com` and no real
Binance credentials of its own. The mock server implements the same two
endpoints (`/fapi/v1/exchangeInfo`, `/fapi/v1/order`) with schema-correct
responses, so every layer of the bot (client, signing, validation,
logging, error handling) is exercised exactly as it would be against the
real testnet — only the server on the other end is fake.

Sequence captured in this log:
1. `BTCUSDT BUY MARKET 0.01` → filled instantly (as MARKET orders are)
2. `BTCUSDT SELL LIMIT 0.01 @ 65000` → resting on the book, unfilled (`NEW`)
3. `BTCUSDT SELL STOP_LIMIT 0.01 @ 64000, stop 64500` → resting, unfilled (`NEW`)
4. `DOGEUSDT BUY MARKET 0.01` → rejected before submission (symbol not on
   the tradable-symbols list), demonstrating the error-logging path

**To produce the real deliverable log** (against actual Binance Futures
Testnet), run the same three commands with `BINANCE_BASE_URL` unset (it
defaults to `https://testnet.binancefuture.com`) and real API credentials
in `.env`. See the main `README.md` → "Running Against the Real Testnet".
